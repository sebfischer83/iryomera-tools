# Iryomera Tools — binding development rules

- Scope and sequence: Foundation → MedicalImporter → ContentStudio → ModKit → ModIo. Only implement the requested phase. Planned tools must not be represented by dummy implementations.
- Target .NET 10, C#, Windows and Linux. Keep Content.SDK independent of Godot, Blazor, EF/SQLite and mod.io. UI, persistence and distribution depend inward on the SDK.
- MIT covers our code and synthetic examples only. Preserve upstream data licenses and per-record provenance. Never commit restricted datasets, proprietary game data, credentials or purchased assets.
- Do not invent medical facts, associations, criteria or recommendations. Import does not imply approval. Keep medical provenance/review separate from simulation balancing; label synthetic examples.
- Stable namespace IDs, external identifiers and localization keys are different concepts. Do not change IDs on language switches. Keep relations as independent records with provenance, version and review status.
- Public JSON changes require synchronized versioned schemas, docs, examples and tests. Preserve additive extension fields. Breaking changes need a new schema version and migration decision.
- Use System.Text.Json, async I/O and cancellation. Use established libraries for version ranges and localized formatting. Keep deterministic validation with explicit dependency inputs and useful paths/codes.
- Run Release build, relevant tests and package checks after material changes. Test error cases and schema/example compatibility, not just happy paths. Do not claim success when checks cannot run.
- Add architecture decisions to docs/architecture. Read docs/plans before changing scope. Prefer small comprehensible changes and no unnecessary external services.
- English is authoritative for repository/API documentation, ADRs and format specifications. Clearly label supplementary translations, link their English reference and update it first when behavior/contracts change. Keep English/German UI and content localization support.
- Future imports must be reproducible, licensed and auditable. Future ZIP handling must enforce traversal/size limits. Never execute mod scripts or DLLs automatically.
- Consult current official documentation when integrating external APIs. mod.io is optional and requires mock HTTP tests; no live requests without explicit configuration.

- Foundation review: SDK and Localization target net8.0/net10.0; build with .NET 10 and test both runtimes. Keep Godot out of library dependencies; verify packed net8.0 binaries in the pinned real Godot integration test on Windows/Linux.
- Preserve lossless MedicalAnnotation context; never flatten negation/frequency/qualifiers or MAxO disease/extension context into unconditional medical/gameplay relations. Keep observational frequency as original source text.
- Validate original JSON at boundaries with ContentDocuments/LocalizationDocuments. Schema-required schemaVersion must be present even when C# construction has a default. Do not remove JsonRequired or silently weaken schema checks.
- MedicalImporter staging v1 is strict/versioned independently of the additive SDK format. Preserve original source fields, exact source versions/licenses, review history and redistribution decisions; see docs/medical-importer.md and docs/data-sources/README.md.
- Never flatten contextual/negative HPO or multi-way MAxO assertions into unconditional medical relations. Keep the full approved source-assertion sidecar. Text/synonym matching proposes candidates only.
- Import/review/export and rights review are separate operations. Export only approved reference-closed selections; never leak rejected/unreviewed source records through release reports. No real data approval or rights grant follows from synthetic tests.

- Phase 2 review: batch redistribution permission never overrides record-specific additional rights or denial. Re-evaluate HPOA IEA/OMIM restrictions from raw claims, including legacy workspaces. Require scoped permission evidence; retain selected rights/review lineage.
- Controlled bulk approval must log every automatic/manual exclusion and revoke prior approval for excluded records atomically. Preserve full immutable histories. Identical cross-batch assertions retain every approved provenance; real conflicts remain errors.
- LOINC 1.1.0 imports are observations, never automatic playable examinations. Old 1.0.0 batches remain readable with their original identities. Bump the adapter identity whenever normalized output rules change.
- Full-dataset tests are opt-in. Never download restricted/account-based data or publish medical input/normalized files via test artifacts; publish aggregate reports only. Pin releases, input/output hashes, counts and expected errors. A matching error baseline is not a medically or semantically valid release.

- Diagnostic contracts: reuse ExaminationDefinition and ObservationDefinition. Medical result descriptors/ranges/recommendations retain source/review; invented probabilities, duration, visibility and repeat policies belong to explicitly simulation-only configuration. Preserve neutral LOINC observations without an asserted Result. See ADR 0008.
- Patient state, seeded PRNG, cached results, diagnostic AI and disease progression belong exclusively to the private game. Do not add a simulator or a dependency on that repository here. Data mods never require execution of foreign code.
- Wikidata: retain Q/P/statement identities, ranks, references, qualifiers and raw bindings. Missing context stays unresolved; explicit identifiers propose matches only. Deprecated/incomplete/unreferenced claims must not enter controlled bulk approval unnoticed. Do not infer clinical approval from CC0.
- Studio: use short-lived EF contexts, migrations, optimistic revisions and atomic index/audit updates. Preserve immutable importer snapshots, extensions and source-specific rights gates. Medical/translation edits revoke affected approval; simulation edits remain separate. Export only approved reference-closed bilingual selections, with scoped source proof and current permissions. Local operator labels are not authentication.

- ModKit v1: explicit typed/licensed inventories and SHA-256 indexes, bounded streaming and staged atomic publication. Never overwrite destinations or extract before checking paths, duplicates, links/special entries, counts, central-directory bounds, sizes and ratio. Reject executable payload types and external GLB URIs; never load assets as code. Preserve SDK provenance and original file bytes. See ADR 0010 and docs/modkit.md.
- SDK asset/placement fields are optional and omitted when null; preserve legacy hashes. Shared language-specific alias handling lives in Localization, and cannot suppress required shared-key translations. CLI packaging is technical validation, never clinical approval or legal permission.
