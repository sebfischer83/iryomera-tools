# Phase 3 — local ContentStudio

Implement only ContentStudio on the reviewed Phase 2 branch. No medical production data acquisition, ModKit or mod.io.

1. Add ASP.NET Core/Blazor Interactive Server net10 host, project/service/data/UI folders and SQLite EF Core migrations. Portable SDK/Localization remain independent; Studio may reference importer application APIs. One short-lived DbContext per operation via IDbContextFactory, optimistic revisions and transactions protect concurrent circuits.
2. Persist projects as complete schema-preserving SDK aggregates, separate translation catalogs, immutable original import snapshots/current append-only review state, normalized searchable definition index and edit/rights audit. Keep source metadata/extensions intact; never edit raw imported claims. Public interchange remains the SDK and importer contracts.
3. Implement tested services for project creation, synthetic loading, raw JSON/schema import, search/filter/paging, typed definition editing/creation, classification/synonym editing, typed relation and contextual annotation editing, separate gameplay/resources, translation editing, validation/duplicate candidates, explicit reviews and rights decisions. Medical edits invalidate approval and dependent relationship approvals; gameplay edits do not change medical facts.
4. Import Phase 2 workspaces, compare IDs/labels/types with projects, browse raw terms/assertions/provenance and diagnostics, review records/batches and record scoped rights using existing gates. Promote only a successfully reviewed/right-cleared importer release to an editable project; keep the source snapshot/binding for export rechecks.
5. Add bilingual UI catalogs via the existing Localization adapter, local assets only, responsive functional pages, source/audit views and accessible SVG relationship editor. Support all current definition kinds; do not manufacture unsupported medical assignments.
6. Export approved reference-closed content, actual available catalogs, source/license/review records. Require project rights and additional record permissions where applicable. Imported source rights/revocations are rechecked. Preserve approved-only behavior, missing-language diagnostics and atomic operations.
7. Test real SQLite migrations/reopen, rollback/concurrency, source immutability, permissions/revocation, validation, translations, review invalidation, exports and HTTP hosting. Exercise the actual UI with a browser on Linux and Windows CI. Document startup, storage/backup, formats, supported workflows and capacity/trust limits. Run full Release build/tests and existing examples/Godot integration.
