# Wikidata importer implementation plan

1. Verify official SPARQL result formats, Wikidata statement/qualifier/reference/rank RDF structure, property identities and CC0. Record exact supported query profile, retrieval/revision metadata and limitations. No live medical data query or optional network client is necessary for the first offline adapter.
2. Add a registered WikidataAdapter for saved SPARQL SELECT JSON/CSV with a documented long-row profile. Use Q IDs (not labels) for identity. Import the explicitly selected disease items and labelled medical targets; do not infer classifications for ambiguous cause entities or merge by text.
3. Preserve complete binding/CSV rows and normalized statement ID, P ID, value, rank, references and qualifiers. Missing metadata remains missing and is diagnosed. All terms/assertions remain unreviewed; deprecated statements cannot pass release, incomplete/unreferenced statements are excluded from bulk approval and require explicit individual review.
4. Add optional bilingual term metadata and explicit external identifiers to staging, keeping old adapter output byte-compatible by omitting absent new properties. Export real en/de labels/descriptions and preserve independent-language aliases without inventing alias translations.
5. Offer HPO/MAxO/ICD identifier-based match candidates only. P3841 is HPO, P494 is ICD-10, P493 ICD-9, P4229 ICD-10-CM and P7807 ICD-11 Foundation. Official property search found no MAxO-specific property; accept an explicit system/ID binding instead of inventing one. ICD-10 codes can offer explicitly labelled ICD10GM comparison candidates, not equivalence/aliases. P780/P923/P924/P828 statements keep exact semantics and context in the source sidecar; no unconditional clinical relation is inferred.
6. Extend strict importer schemas additively, document old-reader/new-enum compatibility, adapter identity and preservation. Reuse existing review, source rights, resolution and export gates. Keep original seven adapter hashes unchanged.
7. Add own synthetic SPARQL JSON/CSV fixtures and tests for languages/aliases, Q identity, qualifier/reference aggregation, rank, missing/unresolved values, explicit candidates, malformed formats, no auto approval, schema compatibility, deterministic repeat and approved export. Update CLI source/matching docs and Windows/Linux CI.
8. Continue the already authorized Studio implementation using this adapter's staged workspace. Diagnostic SDK extensions are a separate additive contract task; actual patient simulation belongs to the private game.
