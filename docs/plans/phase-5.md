# Phase 5 — optional mod.io distribution

1. Merge verified Phase 4 into main, then work on `feature/phase-5-modio`. Inspect the official REST reference, introduction/filtering guides and OpenAPI before implementing endpoints. Never make live account/game API calls without explicit configuration.
2. Add portable `Iryomera.ModIo` (net8/net10): HttpClient REST DTOs/client, email authentication, search/details, subscriptions, paginated dependency graph resolution, release/update checks and multipart publication/uploads. Use DI, async I/O and CancellationToken. Keep API keys/tokens out of default logs, exceptions, serialized configuration and repository fixtures. Bound responses and expose rate limits without retrying writes.
3. Separate bounded credential-free HTTPS downloading from the API client. Verify exact sizes and mod.io MD5, additionally calculate SHA-256, follow only explicit allowed HTTPS redirect hosts and publish downloads atomically. Do not treat MD5 or ZIP indexes as publisher signatures.
4. Define distribution-neutral source/installer/runtime abstractions in the portable library. Local archive sources require no mod.io configuration or network. Add optional `Iryomera.ModIo.ModKit` (net8/net10) for validated installation and publication; extract existing reusable ModKit APIs into `Iryomera.ModKit.Core` (net8/net10), since a NuGet tool package cannot be a normal library dependency. CLI and bridge depend on Core; ModKit never depends on ModIo. Keep private patient/game/asset execution out of Tools.
5. Use existing SDK/ModKit schemas unchanged. Document upstream response DTOs as upstream contracts, and introduce versioned offline schema-validated installation receipts containing local content identity/hash and optional remote IDs, never tokens or signed URLs.
6. Add synthetic mock-HTTP tests on net8/net10 and real ModKit bridge tests, including auth/redaction, pagination/rate limits, redirects/corruption/cancellation, dependency cycles, update identity and atomic local/remote installation. Add an executable offline mock sample and packed portable binaries to the existing Godot check. No account email, subscription or publication is sent in tests.
7. Update architecture, API/source mapping, usage/examples, schemas, notices, package metadata and CI. Run full Release build/tests/pack and Windows/Linux CI, retaining all prior tests. Record exact tested commits, observed outcomes and remaining limitations before reporting completion.
