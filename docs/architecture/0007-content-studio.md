# ADR 0007 — local draft authoring with immutable source snapshots

Status: accepted, Phase 3.

ContentStudio is a net10 ASP.NET Core Blazor Interactive Server host. Components depend on scoped application services; services use short-lived SQLite EF Core contexts from IDbContextFactory. The SDK and Localization retain their net8/net10 targets and acquire no database/UI dependency. The host references the existing MedicalImporter application API to preserve source-specific gates rather than reimplementing import adapters.

SQLite stores complete SDK package/catalog JSON snapshots to preserve extension fields, with a normalized definition index for SQL search/paging, optimistic aggregate revision tokens, transactionally updated audit entries, immutable uploaded importer snapshots and current review state. This is a local authoring database, not a clinical record system. EF migrations create/update schema; no EnsureCreated shortcut replaces migrations. Per-operation contexts avoid Blazor circuit context sharing. A single local operator is trusted; identities are audit labels, not authenticated clinical credentials.

Projects contain editable drafts. Imports validate original wire schemas before defaults, and may retain schema-valid semantically invalid content for repair; new edits cannot introduce additional semantic errors. Approval/export require valid reference closure. IDs and definition kinds are immutable after creation. Medical/translation edits reset affected review metadata and dependent relation/annotation approval; balancing is explicitly simulation-only and independent. Raw imported terms/source fields are never overwritten by authoring changes. Editor revisions and provenance record what changed.

Phase 2 workspaces are imported separately. Review and rights decisions call existing importer APIs. Promotion first passes the existing approved-only ReleaseExporter; the resulting project remains a draft and records its source snapshot. Export rechecks current source rights/selection so a later revocation cannot be bypassed via a promoted project. Project rights are a separate auditable gate. Additional OMIM/IEA/third-party conditions on directly uploaded content require record permissions tied to the record's content digest. No medical facts or cross-source equivalences are inferred.

The UI uses separate en/de JSON catalogs and the existing IStringLocalizer adapter, cookie culture switching and local static assets. The server binds loopback by default. JSON uploads are size-bounded, filenames are display-only, and culture return URLs remain local. Download ZIPs contain fixed SDK/catalog/license/report paths, are not ModKit packages and are never accepted for extraction. No source dataset is seeded/downloaded automatically; loading the own MIT synthetic examples is explicit.

Repository documentation specifies the default data path, backup/export behavior, supported editing and import scope, concurrency failures and remaining limits. Large production datasets and multi-user/authenticated hosting are future capacity/security work, not implied by the local synthetic editor.
