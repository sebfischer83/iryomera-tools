# ADR 0008 — reusable examinations, observations and diagnostic content

Status: accepted for engine-independent contracts; patient runtime and AI are planned exclusively for private Iryomera-Game.

## Existing contracts and meaning

Retain DiseaseDefinition, SymptomDefinition, FindingDefinition, ExaminationDefinition, ObservationDefinition and TreatmentDefinition. Symptoms are subjective reports; findings are objective clinical signs; an observation describes a measurable/qualitative result parameter, not a patient instance; an examination is a reusable action able to produce multiple observations. Existing neutral LOINC observation codes remain valid without a Result descriptor. A disease never owns copies of examination definitions. Hundreds of diseases can reference a shared 30–50 examination catalog; the fictional vertical slice starts with five shared examinations and three diseases.

ObservationDefinition.Result is optional and describes numeric/unit, categorical options (optionally linked to finding definitions), boolean or text results. No runtime measured values or disease probabilities are inserted into this medical definition. PatientContextKeys declare external patient-factor keys used by reference context. PatientContextCriterion is a small conjunction of numeric bounds/category/boolean conditions, never executable code or a script.

Independent examinationObservation, examinationRoom, examinationQualification and examinationPrerequisite relations complement the existing examinationEquipment relation; prerequisites are acyclic. They retain normal IDs/version/provenance/review and dependency resolution. ObservationReferenceRange is a separate sourced assertion with explicit unit, ordered numeric bounds, patient-context conditions and mandatory evidence. Units are exact codes (prefer UCUM); no conversion or clinical interval is inferred. A reference interval is not automatically approved. The examples use fictional unitless intervals with explicit fictional provenance, not real clinical reference values.

DiagnosticRecommendation is a separate optional sourced/reviewed disease/examination-context assertion. It requires evidence and can reference symptoms/findings/observations plus context conditions and rationale localization. It does not prescribe an executable fixed order for an AI physician, nor is it generated from a label match or an importer's gameplay guess.

## Simulation boundary and private runtime plan

DiagnosticSimulationSettings is explicitly simulationOnly and holds SimulatedObservationDistribution, SimulatedManifestation and ExaminationResultPolicy records. Distributions map a disease/context to authored numeric intervals, category weights, boolean probability or a text key. Manifestation probabilities and visibility are game parameters. Repeat policies default to UntilPatientStateChanges; time-based repeats need a positive explicit interval. Existing GameplayBalance retains costs/difficulty/resources; ExaminationDurationSeconds is additive. These parameters are never put in medical provenance/evidence or attributed to HPO/Wikidata/MAxO/LOINC.

The private game will create a patient using a stable, versioned seeded PRNG, selected diseases and patient-factor state. It must generate latent symptoms/findings/observations once, persist seed/algorithm version/state version and cached observations, then make examinations reveal matching existing results. Results cache by patient-state version + observation identity; repeating an examination without a state transition returns consistent results. A time-based repeat requires an explicit elapsed interval and modeled state transition, not a new arbitrary contradictory sample. Multi-output examinations share the same patient observation values. Savegames own that live state; this repository contains no patient classes, random generator, diagnostic executor, doctor AI or treatment/progression simulator.

The private planner should maintain differential diagnoses from known findings/symptoms, score available examinations using simulated expected information gain, elapsed duration/cost/urgency and resource/qualification availability, and use reviewed recommendations as optional context. It should consider already known results and prerequisite closure. Expected utility comes from the game's explicit simulation distributions, not purported clinical likelihoods mined from names. Diagnosis decisions and treatment/progression belong to the game and require separately tested seeded scenarios.

## Studio / Godot / mods / compatibility

Studio edits shared examinations once, result descriptors, independent output/resource/prerequisite relations, reference intervals, recommendations, source/review and separate simulation settings. It must preserve unknown extension fields, show units/context/evidence, invalidate medical approval on medical changes, and require appropriate rights. UI implementation may initially expose advanced structured contracts in validated JSON panels; richer individual widgets can follow without changing formats. No stored source claim is rewritten by a gameplay edit.

Godot loads the same validated net8.0 package; tooling uses net10.0. Definitions are immutable input snapshots for the private runtime. IDs and localization keys never depend on language. Mods can add definitions and relations or reference observations/examinations from explicit namespace dependencies; duplicate IDs, missing dependencies, wrong endpoint types and prerequisite cycles fail. No C# DLL or mod script is needed.

The v1 schema bundle is additively extended with optional collections/descriptors and new explicit enum values. Existing valid v1 JSON/examples still load with unchanged IDs; new contracts require an updated reader, and unknown enum values remain errors in older binaries. Dedicated entry schemas and JsonRequired schemaVersion exist for version-bearing new records. Public package version identifies library capability; schemaVersion remains 1.0.0 for this backward-readable additive extension.

Open runtime questions: exact PRNG algorithm/version, state-transition cadence, multi-disease distribution composition, overlapping context precedence, supported unit conversion, demographic reference-factor vocabularies and AI utility calibration. No clinical answers or medical reference values are guessed here. See the plan and synthetic diagnostics examples for the tested definition-only slice.
