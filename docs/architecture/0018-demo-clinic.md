# ADR 0018 — demo clinic package and furniture equipment

Status: accepted on 2026-10-18, implemented for library 0.14.0.

## Context

For milestone M7 the game replaces its local demo fixtures with SDK content. The game supplied its fixture values (room types, departments, examinations, five fictional cases with deterministic readings, staff roles, furniture with catalog assets and patient names). In the game, placed furniture such as an analyser gives a room an equipment capability that examinations require. The SDK linked examinations to medical equipment and rooms to furniture, but had no way to say which furniture provides which equipment.

## Decision

- New relation `furnitureEquipment` (furniture → medical equipment), owner decision. Examinations keep requiring capabilities through `examinationEquipment`; the game derives a room's capabilities from its placed furniture. `RoomContents.ProvidedEquipment` aggregates them.
- The demo clinic is generated by `scripts/generate-demo-clinic.py` from the committed game fixture input `examples/demo-clinic/source/game-fixtures.json` into `examples/demo-clinic` (package plus en/de catalogs). CI regenerates it and fails on drift.
- Every record is MIT, unreviewed and labelled as fictional demo content; each keeps its original game key in `provenance.externalId`. IDs use namespace `demo_clinic`; hyphens become underscores and observations get the prefix `observation_` because examinations and observations share local keys in the game.
- Case readings are deterministic simulation-only distributions (numeric minimum equal to maximum, one category weight, or a text key). No reference ranges, recommendations or medical relations are generated.
- Wheelchair and stretcher are `pushable` with transport. Their seat, lying and handle points are placeholders (extension field `placeholder: true`) until the game supplies geometry (owner decision).
- Since 0.14.1 the input carries mounts and surfaces (game asset stage 2b, 14 items). Surface heights are placeholders (`placeholder: true`) because the game takes them from the model.
- Since 0.14.2 the game can supply interaction points per item. The CT scanner (2 × 3 cells, catalog asset `equipment.ct_scanner_basic`, ID unchanged for savegames) and the stretcher have measured lying points; their operator and handle points stay placeholders.
- Fixture values without an SDK contract stay in the game: `serviceOnly` departments and per-patient mobility.

## Consequences

The new relation kind needs a 0.14.0 reader. Changing the demo clinic means changing the fixture input or the generator and regenerating; the output is not edited by hand. Unit codes are mapped to UCUM (`Cel`, `/min`, and dimensionless annotations for fictional scales); the game maps them back by observation ID.
