# ADR 0009 — offline Wikidata statements and bilingual source metadata

Status: accepted. Official documentation checked 2026-10-16: [structured-data CC0](https://www.wikidata.org/wiki/Wikidata:Licensing), [statement model](https://www.wikidata.org/wiki/Help:Statements), [ranks](https://www.wikidata.org/wiki/Help:Ranking), [SPARQL](https://www.wikidata.org/wiki/Wikidata:SPARQL_tutorial). Property labels/descriptions were verified through the official wbgetentities API.

Register an offline JSON/CSV adapter for the documented saved SELECT-result profile, not arbitrary Wikidata entity dumps. Medical property identities are P780 symptoms/signs, P923 medical examination, P924 possible treatment and P828 has cause. Preserve source meaning; do not interpret a possible treatment as a clinical recommendation. SourceAssertionKind.WikidataStatement holds exact P ID, statement URI, main value, rank and the complete SPARQL rows. JSON bindings keep language/datatype/type; CSV retains what its format actually contains. References and qualifiers retain original row structure, including reference/property/value identity. Cartesian duplicates are deduplicated without dropping distinct evidence/qualifier rows. Missing metadata is not fabricated.

Disease item identity is WIKIDATA:Q<number>, encoded into the existing stable namespace content-ID rule. Labels never determine IDs. Optional term Translations (en/de label/description/aliases) and ExternalIdentifiers are staging extensions; absent fields stay absent on other sources, preserving all seven existing adapter digest pins. Wikidata uses adapter 1.2.0 while existing sources remain 1.1.0 (legacy 1.0.0 remains readable). Require actual retrievedAt separately from importedAt and CC0-1.0 metadata. CC0 does not grant clinical truth; linked third-party articles are not downloaded/copied or relicensed.

Labels/descriptions export into real en/de catalogs. Independent aliases cannot be paired by array index as purported translations. Their stable language-qualified catalog keys are recorded in localizedAliasKeys and sourceClaims. They are not added to shared SynonymKeys requiring false bilingual pairing. Consumers preserve/use that language map explicitly; source aliases survive even when a translation is absent.

P780 covers both subjective symptoms and objective signs: require explicit valueKind before assigning one of those definition kinds. P923/P924 identify examination/treatment roles; ambiguous/missing role/label targets and untyped cause entities remain unresolved references, never guessed disease/finding definitions. Exact identifiers from P3841 (HPO), P494 (ICD-10), P493 (ICD-9), P4229 (ICD-10-CM), P7807 (ICD-11 Foundation) and explicit external system/ID bindings can offer review candidates. No MAxO-specific property was found in the official property search; no property is invented. Explicit MAxO bindings require source verification by the query author. ICD10 vs ICD10GM is a classification-family candidate, not equivalence. None of these candidate IDs enters AlternateIds or automatic reference resolution.

Raw terms and statements start unreviewed. Controlled bulk review excludes deprecated, unreferenced and incomplete statements (and unresolved endpoints). Deprecated statements cannot be approved/exported even by manually setting status. An individually reviewed unreferenced/contextual statement can remain a sourced claim with honest missing original evidence and audit note; it is not projected into an unconditional medical relation. All Wikidata statements export through the existing lossless sidecar because canonical HPO/MAxO annotation shapes cannot represent every disease-to-cause/examination/treatment claim without changing its direction/type. No source-derived GameplayBalance or simulation distribution is generated.

The bundled query is bounded as a starting example. LIMIT can truncate an entity's evidence/aliases; a saved partial query is not an entity-completeness guarantee. Query authors must preserve whole statements, record query/snapshot version and understand CSV's loss of binding datatypes. Live SPARQL download is optional future work; no network request occurs during import, tests or review.
